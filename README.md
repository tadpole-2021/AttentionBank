# AttentionBank · 注意力银行

**把娱乐时间变成自己赚来的时间。**

注意力银行是一款 Android 自律工具：将学习、阅读等 App 设为“收集时间 App”，使用它们赚取时间余额；将短视频、游戏等 App 设为“娱乐 App”，使用时消耗余额。余额归零后，应用尝试展示拦截页面，或将娱乐 App 退到后台并提醒用户先赚取时间。

它不是一刀切的锁机工具，而是一个围绕“先投入，再娱乐”设计的本地时间账户。

> 当前版本：`0.1.0`，个人使用与真机迭代阶段的 MVP。支持 Android 10 及以上，无需账号，不依赖业务服务器。核心流程已获开发者手机实测反馈，但尚不代表所有 Android 版本和厂商 ROM 均已验证。

## GitHub Description

注意力银行：用学习、阅读等 App 的使用时间赚取娱乐额度，支持独立消耗倍率、每日基础额度、单日结转与零余额拦截的 Android 自律工具。

## 核心功能

| 功能 | 当前实现 |
| --- | --- |
| 单页首页 | 总余额、结转余额、今日已赚和今日已花集中展示 |
| 收集时间 App | 搜索并勾选应用，按 1:1 赚取娱乐余额 |
| 娱乐 App | 每个应用独立设置 0.5、1 或 2 倍消耗 |
| 应用图标 | 选择列表与首页已选应用显示本机 App 图标 |
| 每日基础额度 | 每个业务日发放 600 秒，以本地时间 01:00 为日界线 |
| 单层结转 | 今日剩余额度可留到下一业务日，更早的结转额度到期清零 |
| 零余额拦截 | 独立余额页面；系统不允许自动打开时，单次返回桌面兜底 |
| 耗尽提醒 | 余额耗尽通知、返回桌面时的简短提示；通知可点击进入余额页面 |
| 常驻余额通知 | 显示“注意力银行正在守护你的额度”和当前余额，静默更新 |
| 权限引导 | 使用情况访问、无障碍、忽略电池优化、余额提醒通知 |
| 本地数据 | Room 保存应用分类、余额和收支流水；SharedPreferences 保存运行与诊断信息 |
| 调试摘要 | 当前版本保留首页调试面板，便于排查机型兼容问题 |

详细交互、规则与示例见 [功能说明](docs/FEATURES.md)。

## 时间怎样赚、怎样花

### 三类应用

- **收集时间 App**：每使用 1 秒，赚取 1 秒余额。
- **娱乐 App**：每使用 1 秒，按该 App 的消耗倍率扣减余额。
- **普通 App**：未加入前两类的应用，不赚取也不消耗余额。

同一包名只能属于一类。把一个已分类的 App 勾选进另一类，会移动它的分类，而不是同时计入两类。

### 消耗倍率

| 显示选项 | 说明 | 实际使用 10 分钟消耗的余额 |
| --- | --- | --- |
| `1:0.5` | 宽松 | 5 分钟 |
| `1:1` | 标准，默认 | 10 分钟 |
| `1:2` | 严格 | 20 分钟 |

余额以秒显示，不足 1 秒的倍率扣减通过余数累计。余额不会扣为负数。

### 每日到账与结转

首次初始化账户发放完整的 10 分钟。此后以设备本地时间每天 **01:00** 为结算边界：

1. 清除上一业务日继承的结转余额。
2. 将刚结束业务日的“今日余额”转入新的结转余额。
3. 为新业务日发放 10 分钟。

消费优先使用结转余额，再使用今日余额。引擎正常运行时会检查日结；如果跨日时服务未运行，下次运行或打开应用时补做结算，而不是依赖精确闹钟。

例如：初始余额 `10:00`，阅读 20 分钟后变为 `30:00`，再以标准倍率使用娱乐 App 5 分钟后变为 `25:00`。示例假设同一业务日内、前台识别正常。

## 开始使用

1. 安装自行构建的 APK，打开注意力银行。
2. 在“权限与保活”中开启使用情况访问、无障碍服务和忽略电池优化。
3. 开启“余额提醒通知”。需要显眼提醒时，也在系统设置中允许该通知渠道显示横幅。
4. 点击“收集时间 App”，搜索并勾选用于赚取时间的应用，点击“完成”返回。
5. 点击“娱乐 App”，勾选受限应用，并按需设置倍率。
6. 打开所选 App，观察首页或常驻通知中的余额变化。

首页不需要手动点击“启动引擎”。使用情况访问权限就绪后，界面会尝试自动启动前台服务；要让拦截正常工作，还必须开启无障碍服务。

四项授权状态均满足时，“权限与保活”卡片自动隐藏。权限被撤销后，返回首页会重新检查。部分手机还需手动允许自启动或后台运行。

### 余额用完后会发生什么

- 优先由无障碍服务打开注意力银行自己的“余额已用完”页面，不使用常驻覆盖浮层。
- 如果系统拒绝自动打开页面，尝试返回桌面，让娱乐 App 退到后台，并显示简短提示。
- 允许通知时发送可点击的耗尽通知；进入余额页面或余额恢复后撤销该提醒。
- 余额页面提供“去首页查看”和“返回桌面”，没有临时透支或跳过入口。
- 页面取得前台后申请音频焦点，尽量让播放器停止播放；不能保证强制停止所有第三方后台播放。

返回桌面不等于杀死或卸载目标应用。余额为零时再次进入已配置的娱乐 App，会重新检查并拦截。

## 从源码构建

所需环境：**JDK 17、Android SDK Platform 35**，以及支持 Android Gradle Plugin 8.7 的 Android Studio。最低运行版本为 Android 10 / API 29。

用 Android Studio 打开项目根目录，配置本机 Android SDK 并同步 Gradle。`local.properties` 为本机配置，不应上传。

Windows PowerShell：

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug
```

macOS / Linux：

```bash
sh ./gradlew testDebugUnitTest assembleDebug
```

调试安装包输出：

```text
app/build/outputs/apk/debug/app-debug.apk
```

首次构建需要联网下载 Gradle 和依赖；App 的核心功能不要求运行时联网。当前 APK 是调试包，不是已完成签名、瘦身和商店审核的正式发行包。

完整构建、架构和发布准备见 [开发说明](docs/DEVELOPMENT.md)。

## 当前边界

- Android 和厂商系统可限制后台运行、后台启动页面及通知，不能承诺服务永不被杀或所有机型都实时拦截。
- 尚未完成服务中断后的 UsageStats 历史对账；锁屏、分屏、画中画等场景的计时仍需完善与验证。
- 使用设备本地时间结算，尚未实现针对修改时间或时区的防篡改处理。
- 系统应用保护目前依赖常见包名前缀，不是所有品牌的完整白名单。不要把电话、短信、设置和桌面加入娱乐分类。
- 当前前台服务使用 `dataSync` 类型；面向 Android 15 长时间运行及正式上架前，需要重新评估其适用性和运行限制。
- 日报、7 日图表、低余额提前预警、应急额度、数据导出、账号和云同步均未实现。
- 不承诺旧构思中提出的耗电、误差、启动速度、APK 大小等量化目标已经达成。

具体待完善项见 [开发说明中的发布清单](docs/DEVELOPMENT.md#发布前检查清单)。

## 数据与隐私

当前业务数据在本机保存，没有账号系统、云同步、广告或远程日志上传实现。调试信息含应用包名、余额和时间，分享截图时请注意个人隐私。

无障碍逻辑用于读取应用窗口包名和执行返回桌面的系统动作，当前代码不读取页面文字内容。不过配置声明了窗口内容访问能力，安装时仍应认真审阅授权说明。

Manifest 仍声明 `INTERNET`，且启用了 `allowBackup`。因此这里的“本地保存”不等于“系统绝不会备份数据”；系统备份行为取决于设备设置。公开发行前应进一步收敛权限和明确备份政策。
